Windows, before you walk away

10 minutes — do these, then move to the Mac
Commit and push everything Windows Blocker
Your working tree has ~35 modified files that are not on origin/main — including the CP-80 native-app fixes and the updated privacy policy. Two reasons this matters: the Mac clones from GitHub, and the iOS shell loads the live site, so unpushed web work is invisible to the app. Run this in the project root:
git add -A
git commit -m "CP-83: pre-iOS sync — native PWA gating, privacy policy, launch docs"
git push origin main
Then confirm Vercel finished deploying before you test anything on iPhone.
Drop a 1024×1024 app icon into the repo Windows
mobile-shell/resources/ is empty except a README, and your Android launcher icons top out at 192px — too small for iOS. Save your Atlas mark as a 1024×1024 PNG, square, no transparency, no rounded corners (Apple rounds it for you) at mobile-shell/resources/icon.png. Optionally add splash.png (2732×2732). Push it with the commit above. If you don't have a clean 1024 version, tell me and I'll generate one from your logo.
Check your Apple enrollment status Browser
Sign in at developer.apple.com/account. "Your enrollment is being processed" = still pending. If it sits more than ~5 business days, contact Apple Developer Support — pending enrollments do get stuck and only a support ticket unsticks them. Everything in Phase 1 works fine while you wait.
Don't skip the push. The single most common way this goes sideways is cloning on the Mac, building, and testing against a production site that's missing the fixes you made last week — then chasing "bugs" that were already fixed on Windows.
1

Mac setup — free, no Apple account needed

Start now, runs in parallel with Apple's approval
Check your macOS version FIRST Mac Blocker
Apple menu → About This Mac. Since April 28, 2026, every build uploaded to App Store Connect must be compiled with Xcode 26 and the iOS 26 SDK. Xcode 26.4 requires macOS Tahoe 26.2 or later. If your Mac is on an older macOS, update it (System Settings → General → Software Update) before anything else. If your Mac is too old to run Tahoe, stop and tell me — we'd switch to a cloud-Mac or CI build path instead of burning a day.
Start the Xcode download immediately Mac Waiting
Mac App Store → search Xcode → Get. It's 10+ GB and can take hours. Kick it off, then do the next three steps while it downloads. When it finishes: open it once, accept the license, let it install additional components.
Install Node and CocoaPods Mac
Node LTS from nodejs.org. Then CocoaPods (Capacitor's iOS dependency manager) — Homebrew is the least painful route on a modern Mac:
# if you don't have Homebrew:
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

brew install node cocoapods
node -v && pod --version
Clone the repo Mac
Only after Phase 0's push has landed. GitHub will ask for credentials — use a personal access token, not your password.
cd ~/Developer 2>/dev/null || mkdir -p ~/Developer && cd ~/Developer
git clone https://github.com/amonta16/atlas-rewards.git
cd atlas-rewards/mobile-shell
Keep this clone out of OneDrive. Xcode builds and OneDrive sync fight each other badly.
Generate the iOS project Mac
@capacitor/ios isn't in package.json yet (Android-only so far), so install it explicitly before adding the platform:
npm install
npm install @capacitor/ios@^7.0.0
npx cap add ios
npx cap sync ios
This creates mobile-shell/ios/. Capacitor 7 is fully compatible with Xcode 26 — no migration needed. Commit the new ios/ folder when it builds.
Add the two required Info.plist keys Mac Blocker
Open ios/App/App/Info.plist and add inside the top-level <dict>. The camera key is mandatory — the QR scanner crashes without it and Apple rejects builds that use the camera with no usage string. The encryption key saves you an export-compliance popup on every single upload.
<key>NSCameraUsageDescription</key>
<string>Scan your business's QR code to join and check in.</string>
<key>ITSAppUsesNonExemptEncryption</key>
<false/>
Generate the app icon set Mac
With resources/icon.png in place from Phase 0:
npx @capacitor/assets generate --iconBackgroundColor '#ffffff' \
  --iconBackgroundColorDark '#0e7c86' --ios
Otherwise you ship with the default Capacitor logo, which is an instant "this is a template app" signal to a reviewer.
Run it in the Simulator Mac
npx cap open ios → in Xcode pick an iPhone 17 simulator from the device dropdown → press ▶. First build is slow. Expected: Atlas Rewards boots to the join screen.
# if Terminal complains "xcodebuild requires Xcode":
sudo xcode-select -s /Applications/Xcode.app

# if pods fail:
cd ios/App && pod install --repo-update
Run the verify checklist in the Simulator Mac
Join by code → branded business app loads → quit the app entirely and reopen → still logged in, still in that business. That last one is the iOS-specific risk: WKWebView is lazier than Android about persisting cookies. If the session drops, flag it — the fix is a small AppDelegate change, and it's much better to find it now than after a rejection. (Camera and push can't be tested in the Simulator — those need the real phone in Phase 2.)
Everything above is free. None of it needs the paid account to be approved. If Apple approves you mid-way through, great — just continue into Phase 2.
2

Signing, push, and the real iPhone

The moment Apple approves your enrollment
Sign in to Xcode and turn on automatic signing Mac
Xcode → Settings → Accounts → + → sign in with the same Apple ID that owns the paid membership. Then Project navigator → App target → Signing & Capabilities → check "Automatically manage signing" → Team = your name (Personal Team won't work for the App Store; pick the paid one). Xcode creates the certificates and provisioning profiles for you — you don't need to touch the certificates portal manually.
Add the push capabilities Mac
Signing & Capabilities → + Capability → add Push Notifications, then add Background Modes and tick Remote notifications.
Create the APNs Auth Key Browser
developer.apple.com/account → Keys → + → name it "Atlas APNs" → tick Apple Push Notifications service (APNs) → Continue → Register → Download the .p8 file. You can only download it once. Note the Key ID and your Team ID (top-right of the developer portal).
Wire Firebase for iOS Browser Mac
Firebase Console → your Atlas project → Project settings → Add app → iOS → bundle ID com.atlasengine.rewards → download GoogleService-Info.plist and place it in ios/App/App/ (drag it into Xcode's App folder so it's added to the target, not just the filesystem). Then Project settings → Cloud Messaging → iOS app configuration → upload the .p8 with its Key ID and your Team ID. Finally npx cap sync ios.
Known open item from CP-80: the Android equivalent, mobile-shell/android/app/google-services.json, is still missing — Android push cannot work until it's downloaded and dropped in. Same Firebase project, "Add app → Android". Grab both while you're in there.
Test on your actual iPhone Mac Blocker
Plug in, trust the computer, pick it as the run target, press ▶ (you may need to approve the developer profile on the phone: Settings → General → VPN & Device Management). Now verify the things the Simulator can't:
→ QR scanner opens the camera and shows the permission prompt with your usage string
→ scanning a business QR joins correctly
→ push permission prompt appears and a test notification actually arrives
→ quit & reopen → still logged in, still in the right business
→ external links (Google Maps, review links) open in Safari, not trapped in the webview
Do not move to Phase 3 until push works on the real phone. Once you upload a build with broken push you'll be doing 30-minute archive/upload round trips to debug it.

App Store Connect — the paperwork

Can be done in parallel with Phase 2
Create the app record Browser
appstoreconnect.apple.com → Apps → + → New App.
PlatformiOS
NameAtlas Rewards (must be globally unique — if taken, try "Atlas Rewards — Loyalty")
Primary languageEnglish (U.S.)
Bundle IDcom.atlasengine.rewards
SKUATLAS-REWARDS-001 (internal only, never shown)
User AccessFull Access
CategoryPrimary: Lifestyle · Secondary: Shopping
Set availability to United States only Browser
Distribution → Pricing and Availability → Free → deselect all countries except the US. Why: selling in the EU triggers the Digital Services Act "trader" requirement — as an individual you'd have to publish your name, phone number, and home address publicly on your store listing. US-only sidesteps that entirely, and every one of your businesses is local anyway. You can expand later.
Fill the App Privacy questionnaire Browser
This mirrors Google's Data Safety form. Based on your live privacy policy, the honest answers are:
Contact Info → Email, Name, PhoneCollected · linked to identity · App Functionality + Account Management. Not used for tracking.
Other Data → Date of BirthCollected · linked to identity · App Functionality (birthday rewards).
Identifiers → Device IDCollected · linked to identity · App Functionality (push token). Not for tracking.
Usage Data → Product InteractionCollected · linked to identity · Analytics + App Functionality (visits, points, redemptions).
Camera / PhotosNot collected. QR decoding happens on-device; nothing is stored or transmitted. Say so plainly.
Tracking across apps?No. No ad SDKs, no third-party trackers.
Privacy Policy URLhttps://www.atlas-engine.app/legal/privacy
Also confirm the in-app account deletion path is reachable (CP-75) — Apple requires apps with account creation to offer in-app deletion, and reviewers do check.
Age rating questionnaire Browser
Answer "None" across the board — no violence, gambling, mature themes. The prize wheel is a loyalty mechanic with no wagering and no real-money stakes, so it is not gambling; if asked about "contests," describe it as a rewards giveaway. Do not opt into the Kids Category — that pulls in a much stricter rule set you don't want.
Write the listing copy Browser
Subtitle (30 char max), promotional text, description, keywords (100 chars, comma-separated, no spaces), support URL. Starting draft:
Subtitle: Rewards at your local spots Keywords: loyalty,rewards,points,punch card,checkin,qr,local,business,spa,salon,perks Description: Atlas Rewards is your card for the local businesses you already love. Scan the QR code at the front desk, earn points on every visit, and cash them in for real rewards. • Scan to check in — the camera does the work, no punch cards to lose • Watch your points climb and see exactly how close you are to your next reward • Keep a visit streak going and unlock milestone gifts along the way • Spin the prize wheel after you check in • Get a heads-up when a limited-time offer drops at one of your spots • Every business looks like itself — its own colors, its own rewards, its own perks Join a business by scanning its QR code or entering its join code. One account works across every Atlas business you visit.
Support URL: https://www.atlas-engine.app (make sure a contact method is visible on it). Marketing URL is optional.
Capture screenshots Mac
Required size is the 6.9" iPhone (1290×2796 portrait) — Apple scales that down for smaller devices, so one set is enough. Run an iPhone 17 Pro Max simulator, navigate to each screen, ⌘S saves a screenshot to the desktop. Grab 5: 1) home with points card + rewards, 2) the rewards store, 3) QR scan / check-in, 4) streak + prize wheel, 5) a limited offer. Use a demo business with real-looking data — empty states look broken.
Tip: the whole of Phase 3 is browser work. If Apple's approval is dragging, this is what to do with the wait.

Upload, TestFlight, submit

Phases 2 and 3 both done
Set version and build number Mac
Xcode → App target → General → Version 1.0.0, Build 1. Every upload needs a higher build number, even a re-upload of the same version. Bump it before each archive or App Store Connect rejects the binary.
Archive and upload Mac
Device dropdown → Any iOS Device (arm64) (Archive is greyed out while a simulator is selected) → Product → Archive → when the Organizer opens: Distribute App → App Store Connect → Upload → accept the defaults. The build then processes for 15–30 minutes before it appears in App Store Connect.
TestFlight on your own phone Browser
App Store Connect → TestFlight → Internal Testing → add yourself → install through the TestFlight app on your iPhone. No tester minimums, no waiting period — this is your dress rehearsal, and it's the exact binary Apple will review. Run the full checklist one more time here.
Create the demo account and demo QR Browser Blocker
Make a real customer account on a demo business, seeded with points, a claimable reward, an active offer, and a streak in progress. Then export that business's join QR as a PNG. The reviewer is on a desk in Cupertino with no access to your spa — if they can't log in and can't scan anything, you get rejected the same day.
Write the App Review Information notes Browser
This box is your entire defense against a Guideline 4.2 "this is just a website" rejection — the #1 risk for a Capacitor shell that loads a remote URL. Fill in Sign-In Required = Yes, the demo credentials, and paste this into Notes (with the QR attached in the attachment field):
Atlas Rewards is a loyalty app for local businesses (spas, salons, restaurants). Customers join a specific business and earn points for in-person visits. HOW TO REVIEW: 1. Sign in with the demo account above. It is already enrolled in a demo business, so you'll land directly in that business's rewards app. 2. Tap "Check in" and use the QR scanner — the attached QR image can be scanned from another screen or a printout. This awards points and advances the visit streak. This uses the device camera natively. 3. After checking in, the Prize Wheel and streak milestones unlock on the Home tab. 4. Rewards tab: redeem points for a reward. Offers appear as limited-time cards. 5. Push notifications: allow the prompt on first launch. Offer alerts and reward unlocks are delivered via APNs. NATIVE FUNCTIONALITY: the app uses the camera for QR check-in, APNs push notifications for offer and reward alerts, and on-device storage to keep customers signed into their business between launches. Check-in requires physical presence at the business — the QR codes are posted at the front desk — so this is not a repackaged website; the core interaction only makes sense on a phone in a store. Account deletion is available in-app under Profile → Account. Questions: hello@atlas-engine.app
Submit for review Browser
Attach the build to the 1.0.0 version, choose Manually release this version (so you pick the launch moment), then Add for Review → Submit. Typical turnaround is 24–48 hours. If it's rejected, don't rebuild reflexively — most 4.2 rejections are answered in Resolution Center with a clearer explanation and a screen recording of the QR check-in.
The one gotcha that matters most: Guideline 4.2 — Minimum Functionality. A webview pointing at a website gets rejected; a webview whose core loop is scan a physical QR code at a business to earn points, then get pushed an offer gets approved. Your job in the reviewer notes is to make that second sentence impossible to miss. Camera + push + persistent local session are your three native pillars — name all three explicitly.
5

After approval

Ongoing
Release, then remember the day-to-day rule Browser
Because the shell loads www.atlas-engine.app, every feature and fix ships as a web deploy — both apps update instantly, no resubmission. You only rebuild and resubmit for: app icon changes, new native plugins, new permissions, or Apple's annual SDK bump.
Calendar the SDK deadline and the renewal Browser
Apple raises the minimum SDK roughly every April — you'll need to update Xcode and re-archive once a year to stay submittable. The $99 membership also auto-renews annually; if it lapses, your app is pulled from the store.
Universal Links (optional, later)
Associated Domains capability → applinks:atlas-engine.app + host an apple-app-site-association file, alongside Android's assetlinks.json. Makes atlas-engine.app links open the installed app. Nice-to-have, not launch-blocking.
You're done when: a stranger can search "Atlas Rewards" in the App Store, install it, scan the QR at a business's front desk, and watch their points go up.
